# ADR-001 • Web application and server organisation

| Field | Value |
| --- | --- |
| Status | Proposed |
| Context | PA2 Section 3 selected React, Node.js with Express, and PostgreSQL. The team needs a deployment structure that supports Chrome and Safari and applies the same server rules to player booking and owner operations. Drivers: FR-21, FR-22, NFR-01, NFR-04, NFR-06, CON-01, CON-02, ASR-G5 and ASR-G8. |
| Decision | Build one React web client and one Express server organised into modules. Hold, confirmation, in-person booking and schedule blocking use the same scheduling logic. PostgreSQL stores the shared schedule. |
| Alternatives considered | Separate deployment services for booking, owner management and notifications would allow independent releases. A schedule update that also changes bookings and creates notices would require additional coordination. The modular server is proposed for the demo scale and the shared-schedule requirement. |
| Consequences | The component diagram identifies the scheduling component and its callers. The team must define the client–server API. A change to a backend module requires redeploying the server. NFR-06 still needs a performance check with demo data. |
| Review and evidence | React–Express–PostgreSQL connectivity and price read/write were exercised in the feasibility spike. Issue #9 · Issue #12 · Issue #7 · PR #24 |
